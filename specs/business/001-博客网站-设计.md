# 博客网站设计文档

## 1. 需求背景与核心目标

本项目旨在开发一个高度自动化、完全基于 Markdown 的个人博客与作品集网站。满足以下核心诉求：
1. **首页即简历**：首页展示个人自我介绍、项目经历、工作经历与作品集等。
2. **顶部分类导航**：顶部拥有 Menu 菜单，用于切换不同的文章集合（如：每月总结、后端开发等）。
3. **基于文件系统的路由与菜单**：建立一个目录即代表建立一个文章集合，支持多级嵌套，并自动反映在顶部导航栏中。
4. **Git 工作流**：纯 Markdown 写作，通过 `git push` 触发 GitHub Actions，实现自动化构建与发布。
5. **万物皆 Markdown**：无论是博客文章还是首页的简历，全部通过 Markdown 及其 Frontmatter (YAML元数据) 来维护内容。

## 2. 技术选型与架构

为了实现完全基于 Markdown 且具有极佳性能和自定义能力的博客，我们推荐采用现代的 **静态网站生成器 (SSG)**。

- **核心框架推荐**：**VitePress**、**Astro** 或 **Next.js (Nextra)**。
  - **首选推荐：VitePress**。它是专为 Markdown 打造的内容驱动框架。原生支持 Markdown 扩展，内置极佳的代码高亮、前端静态资源构建等特性。最重要的是，通过编写极少量的 Node.js 脚本，就可以轻松实现基于目录结构的自动化 Menu 树生成。
  - **备选方案：Astro**。如果你希望首页（简历）拥有极具个性化、非常复杂的 UI，Astro 对组件化和 Markdown 的混合支持极其强大，并且天生支持基于文件系统的路由。
- **部署方案**：**GitHub Pages**。免费且与 GitHub 的生态完美契合。
- **CI/CD**：**GitHub Actions** 自动化部署流。

## 3. 目录结构与内容组织

核心思路是**“目录即菜单，文件即文章”**。

```text
├── .github/
│   └── workflows/
│       └── deploy.yml        # GitHub Actions 自动化构建与发布配置
├── scripts/
│   └── generate-nav.js       # 核心：根据 content 目录自动生成顶部 Menu 和侧边栏的脚本
├── content/                  # Markdown 内容根目录
│   ├── index.md              # 首页内容（简历、个人介绍信息）
│   ├── 每月总结/             # 一级目录 -> 顶部菜单 "每月总结"
│   │   ├── 2024/             # 二级目录 -> 嵌套菜单 "2024"
│   │   │   ├── 01-总结.md
│   │   │   └── 02-总结.md
│   │   └── 2023/
│   └── 后端开发/             # 一级目录 -> 顶部菜单 "后端开发"
│       ├── Java/
│       └── Go/
├── package.json
└── site.config.js            # 站点配置文件
```

## 4. 核心功能设计

### 4.1 首页（个人简历）设计
在 `content/index.md` 中，利用 Markdown 的 Frontmatter（YAML 元数据）来定义结构化数据（如工作经历、项目列表），结合 Markdown 正文进行渲染。在框架中可以为其指定特殊的布局模式（例如 VitePress 的 `layout: custom`），通过编写专门的 Vue/React 组件来将这些元数据渲染成美观的简历布局，同时保留纯文本配置的便捷性。

### 4.2 自动化 Menu 结构（支持嵌套）
为了实现“新建目录即新建分类”的需求，需开发一个构建阶段脚本（Pre-build Script）：
1. **递归遍历 `content/` 目录**：忽略特殊的系统文件夹和点文件。
2. **生成树状结构**：解析目录层级。如果一个目录下包含子目录或 `.md` 文件，则将其转化为一个菜单项。
3. **映射为导航配置**：将生成的 JSON 树状结构动态注入到网站的顶部导航栏（Nav）配置中。
4. **嵌套支持**：根据文件夹深度生成多级下拉菜单，同理也可为不同的文章集合生成专属的侧边栏（Sidebar）。

### 4.3 自动化构建与部署工作流 (CI/CD)
编写 GitHub Actions 配置文件 `.github/workflows/deploy.yml`，彻底解放双手：
1. **触发条件**：监听主分支（如 `main`）的 `push` 事件。
2. **构建步骤**：
   - 检出代码（Checkout）
   - 设置 Node.js 环境并安装依赖
   - 执行构建命令（在构建前会自动执行 `generate-nav.js` 生成最新的目录结构）。
3. **发布步骤**：
   - 将生成的纯静态文件产物（如 `dist/` 或 `.vitepress/dist/`）自动推送到项目的 GitHub Pages 服务中。

## 5. 理想工作流演示

1. 在本地新建文章：在 `content/后端开发/` 目录下新建一个文件夹 `Spring`。
2. 编写内容：在 `content/后端开发/Spring/` 下新建 `IoC原理.md` 并使用 Markdown 尽情书写。
3. 提交代码：在终端执行 `git add .` -> `git commit -m "add new post"` -> `git push`。
4. 喝口水的时间：GitHub Actions 自动完成构建发布。访问博客域名，顶部菜单自动出现了级联菜单 `后端开发 -> Spring`，点击即可阅读《IoC原理》这篇文章。

## 6. 后续演进路线

- **阶段 1：基础脚手架**：初始化框架（VitePress 等），跑通本地 Markdown 渲染，完成纯静态首页（简历）的基本排版。
- **阶段 2：路由与菜单自动化**：完成 `generate-nav.js` 脚本，实现基于目录的文件树解析和 Menu 自动注入。
- **阶段 3：自动化工作流部署**：配置 GitHub Actions，跑通从本地 `git push` 到线上内容更新的全链路自动化。
- **阶段 4：体验进阶**：增加全局内容搜索（如基于 Algolia 或本地的搜索工具）、增加代码块一键复制、集成基于 GitHub Discussions 的评论系统（如 Giscus）。
