# 博客网站实现计划

本文档基于 `001-博客网站-设计.md` 提取并细化，旨在将设计想法转化为可落地执行的分阶段开发计划。每个阶段均包含明确的任务列表与验收标准。

## 阶段 1：基础脚手架搭建与简历首页开发

**目标**：跑通 VitePress 基础架构，能够本地预览网站，并完成纯 Markdown 结合局部 CSS 的简历首页编排。

**任务列表**：
1. **项目初始化**：
   - 初始化 npm 项目 (`package.json`)。
   - 安装 VitePress 及其相关基础依赖。
   - 配置常用的 npm 脚本（如 `dev`, `build`, `preview`）。
2. **目录结构搭建**：
   - 创建 `content/` 目录作为 Markdown 文章存放的根目录。
   - 创建 `.vitepress/config.js`（或等效的站点配置文件），配置基础的站点信息（Title、Description、Theme 默认配置）。
3. **简历首页开发**：
   - 在 `content/` 目录下新建 `index.md`。
   - 配置 Frontmatter 为 `layout: page`（取消默认侧边栏，提供更宽的展示区域）。
   - 编写个人简历的纯 Markdown 内容（使用 `## 项目经历`、`## 工作经历` 等原生标题和列表格式）。
   - 在 `index.md` 底部或顶部引入 `<style scoped>`，编写自定义 CSS 美化简历结构（例如调整标题边距、字体大小，或将特定区块变成卡片样式）。

**验收标准**：
- [ ] 运行 `npm run dev` 能够成功启动本地服务。
- [ ] 访问首页时，能够看到美观的排版，简历内容均由纯 Markdown 渲染而来。
- [ ] 首页的自定义 CSS 生效，不影响全局其他默认文档的样式。

## 阶段 2：基于目录结构的自动化导航与排序

**目标**：实现“目录即菜单”，支持多级嵌套以及基于前缀序号的智能排序。

**任务列表**：
1. **编写目录扫描脚本**：
   - 在 `scripts/` 目录下创建 `generate-nav.js`（采用 Node.js 的 `fs` 和 `path` 模块）。
   - 递归读取 `content/` 目录，排除 `index.md`、`.vitepress/` 和隐藏文件。
2. **实现前缀解析与排序逻辑**：
   - 使用正则表达式识别目录名和文件名中的数字前缀（例如 `001-xxx.md`）。
   - 按照数字升序或默认字母顺序对同级文件/目录进行排序。
   - 处理名称显示：剔除数字前缀和 `.md` 后缀，生成干净的菜单名称（如 `001-后端开发` 提取为 `后端开发`）。
3. **生成 VitePress 导航配置**：
   - 将扫描与排序结果转换为 VitePress 期望的 `nav`（顶部导航栏）和 `sidebar`（侧边栏）JSON 数据结构。
4. **配置集成**：
   - 在 `.vitepress/config.js` 中动态引入并执行该脚本，使其在每次开发环境启动或正式构建前自动注入最新的路由菜单。

**验收标准**：
- [ ] 在 `content/` 目录下任意新建带有（或不带有）前缀的目录与文件（如 `content/每月总结/2024/001-一月总结.md`）。
- [ ] 重启或刷新本地服务后，顶部导航栏和侧边栏能正确渲染多级级联菜单。
- [ ] 菜单显示名称没有冗余的 `001-` 前缀和 `.md` 后缀。
- [ ] 文章菜单的显示顺序严格按照约定的前缀序号规则进行排列。

## 阶段 3：Git 工作流与 GitHub Actions 自动部署

**目标**：彻底打通从本地 `git push` 到静态网站在线访问的全自动发布链路。

**任务列表**：
1. **Git 仓库配置**：
   - 添加 `.gitignore`（忽略 `node_modules`、`.vitepress/dist` 等、`.vitepress/cache`）。
   - 在 GitHub 创建对应的远程仓库并提交代码。
2. **配置 GitHub Actions**：
   - 在项目根目录创建 `.github/workflows/deploy.yml`。
   - 编写构建流程：监听 `main` 分支的 push 事件 -> checkout 代码 -> setup Node.js 环境 -> `npm install` -> `npm run build`。
   - 编写发布流程：利用 GitHub Pages 的官方 action，将构建产出目录（`.vitepress/dist`）部署到 `gh-pages` 枝或直接发布到 GitHub Pages。
3. **GitHub Pages 权限配置**：
   - 在 GitHub 仓库设置中，开启 GitHub Pages 服务，并授予 GitHub Actions 读取和写入页面的权限（`actions: read`, `pages: write`, `id-token: write`）。

**验收标准**：
- [ ] 仅修改任意一个 Markdown 文件，执行 `git commit` 和 `git push`。
- [ ] 能够在 GitHub 仓库的 "Actions" 面板中看到工作流成功执行（打绿勾）。
- [ ] 通过 `<username>.github.io/<repo-name>` 能够公开访问最新发布的博客。

## 阶段 4：体验进阶与细节优化

**目标**：增强网站的功能性和互动体验。

**任务列表**：
1. **全局内容搜索**：
   - 在 `.vitepress/config.js` 中开启并配置 VitePress 内置的本地搜索功能（Local Search），支持全站中英文标题和正文的快速检索。
2. **评论系统集成（可选）**：
   - 申请 Giscus（基于 GitHub Discussions 的评论系统）。
   - 编写或引入 Vue 组件，在标准的 Markdown 文章底部自动挂载评论区。
3. **功能性组件补充**：
   - 确保文章中的代码块拥有一键复制功能（VitePress 默认支持，需检查样式）。
   - 配置网站的 Favicon 和更好的 Meta 标签（便于 SEO）。
4. **移动端适配与主题微调**：
   - 检查简历首页在手机端的展现效果，微调 CSS 媒体查询以确保响应式体验。

**验收标准**：
- [ ] 点击顶部的搜索框，能瞬间检索出相关 Markdown 文件中的段落。
- [ ] （如集成评论）在文章详情页底部可以正常登录 GitHub 授权并发表评论。
- [ ] 在手机浏览器上访问简历主页时，文本不溢出，菜单能通过汉堡按钮正常展开。
